# AI 使用与验证记录（随开发持续更新）

> 原则：AI 用于提速与辅助，所有关键决策、数值、结论均经人工/自动化验证。

| 工具 | 用途 | 模型 |

## 3. 关键验证记录（示例，逐条填充）

- [x] 证据数值核对：内置快照中的光智科技数据与扶摇真实接口返回一致——营业收入 2024 年 1,454,591,424.31 元、2023 年 1,011,387,440.41 元；归母净利润 2024 年 12,257,095.18 元（=1225.71 万元）、2023 年 -241,033,971.63 元；非经常性损益明细（处置损益 37,831,189.29 元）与 iFinD 公告检索的年报原文一致。
- [x] 防幻觉验证：自动化测试（pipeline.test.ts「防伪造」用例）断言 AI 输出中不出现载荷之外的数值；真实运行中发现并修复两处误伤（载荷 ID 内数字、被零宽字符拆分的年份），已回归。
- [x] 结论可追溯验证：真实运行结果中结论逐条引用证据 ID，证据逐条引用载荷 ID，载荷展示原始接口返回，全程可回溯（scripts/summarize-run.mjs 输出）。
- [x] 合规验证：自动化测试覆盖荐股式输入拦截（「现在该不该买测试股份」→ 引导改写为可验证命题）；真实运行未出现任何买卖建议输出。
- [x] 接口异常验证：真实运行中扶摇 2023 年指标接口返回 code=5003 → 自动降级内置快照并在载荷如实标注；iFinD 限流 → 证据标记降级；故障演示开关可复现全链路降级。

## 4. AI 产物中发现并修正的问题（如实记录）

| # | 问题 | 发现方式 | 修正 |
| --- | --- | --- | --- |
| 1 | AI 在证据/结论文本中直接写出未经载荷确认的数值 | 测试扫描 + 真实运行 | 防伪造扫描：载荷之外的数字替换为「见载荷」并记录 |
| 2 | 防伪造扫描误伤载荷 ID 内的数字（如 P-b9ca6ebc） | 真实运行走查 | 改为只匹配独立数字 token（前后非字母/点/横线） |
| 3 | LLM 偶发零宽字符拆散年份导致误替换 | 真实运行走查 | 先清除零宽字符再扫描 |
| 4 | 证据 LLM 分不清利润表数据点所属年份（报告期字段未识别） | 真实运行走查 | 提取器优先取 fiscal_year 作为报告期上下文 |
| 5 | LLM 给利润表查询写 limit=2 导致缺基期年份 | 真实运行走查 | 适配层强制利润表查询至少取 4 期 |
| 6 | 快照降级证据被误算为「弱证据」导致结论被强制降级 | 真实运行走查 | 只有 empty/error 才算弱证据，degraded（快照兜底）不算 |
