# 命题验证台 · Thesis Lab

把一句投资命题变成 **可验证子问题 + 支持/反对/无法验证证据链 + 可追溯结论 + 结论反转条件** 的 AI 研究助理。

> 同花顺 2026 校招测评 · AI 产品经理岗 ·《投资命题与多证据验证》
> 演示地址：**https://thesis-lab-iota.vercel.app**（Vercel 部署，公开可访问）　源码：https://github.com/breakafantasy/thesis-lab

---

## 快速开始

```bash
npm install
cp .env.example .env.local   # 填入 DEEPSEEK_API_KEY（必需）；扶摇 / iFinD MCP 凭证可选
npm run dev                  # http://localhost:3000
```

不配置任何数据源凭证也能运行主链路：自动降级到内置公开数据快照，并在每条证据上如实标注来源。数据源状态可在页脚查看（`/api/health`）。

## 用户

**目标用户**：会形成投资命题的投资者、研究员——例如「盈利改善来自主营业务」「估值回落但基本面未恶化」这类定性判断的提出者。

**核心场景**：脑海中有一个判断（命题），想知道它是否经得起数据检验，需要一份**能一路回到原始数据**的结论，而不是一句观点。

**不做的事**（反场景）：荐股、涨跌预测、自动交易、回测。

## 产品设计

主链路：

```
命题输入 → ① 澄清与修订 → ② 拆解子问题 → ③ 数据采集 → ④ 证据链构建
        → ⑤ 冲突处理与结论 → ⑥ 结论反转条件 → ⑦ 追问 / 比较 / 保存为研究任务
```

| 环节 | 设计要点 |
| --- | --- |
| ① 澄清与修订 | 只挑会影响结论的关键歧义（标的/时间窗口/指标口径/对比基准/断言方向）逐项确认；修订记录（改了哪里、为什么）随结果保留 |
| ② 拆解子问题 | 每个子问题带验证口径（达到什么程度算支持）与结构化数据查询计划；现有数据源覆盖不了的子问题直接标记「不可验证」 |
| ③ 数据采集 | 统一 `DataProvider` 适配层调用扶摇 / iFinD MCP；失败自动降级内置快照，降级与异常一律写进载荷 |
| ④ 证据链 | 每个子问题 → 支持 / 反对 / 无法验证 / 部分支持 四类证据；每条证据带来源引用与获取时间 |
| ⑤ 冲突处理 | 同子问题下支持与反对并存即显式冲突，按规则仲裁：口径差异 > 时间窗口 > 来源权威性 > 样本量 |
| ⑥ 结论 | 支持 / 部分支持 / 不支持 / 无法判断 + 置信度；结论逐条引用证据 ID |
| ⑦ 反转条件 | 「什么信息变化会改变当前结论」→ 锚定当前数据的触发阈值 + 可监测的数据查询 |
| 追问 / 比较 / 研究任务 | 基于证据链的多轮追问；两个验证结果对比；一键保存、重开、导出 |

**核心机制**：

- **证据账本（可追溯）**：结论 → 证据索引 → 证据 → 数据载荷 → 原始接口返回/公告材料，逐层可点，全程无断链。
- **防伪造红线**：AI 只负责拆解、归类、推理；所有数值只存在于数据载荷。AI 输出经扫描，载荷之外的任何数字一律替换为「见载荷」（自动化测试覆盖）。
- **诚实的第三类**：数据拿不到就是「无法验证」，绝不补全猜测；证据缺失/异常占比 ≥ 1/3 时结论被强制降为「无法判断」。
- **异常降级**：数据源超时/限流/未配置 → 快照兜底并标注来源，或如实标「无法验证」；结论置信度随证据完整度调整。

## AI 角色

| 角色 | 职责 | 边界 |
| --- | --- | --- |
| 命题分析师 | 解析命题要素、生成澄清问题、修订命题、拆解子问题与数据查询计划 | 不脑补用户未确认的口径 |
| 证据组织者 | 把数据载荷组织为四类证据，给出可审计的归类理由 | 不生成任何数值，只能引用载荷 |
| 冲突仲裁者 | 按显式规则仲裁证据冲突 | 规则优先级固定：口径差异 > 时间窗口 > 来源权威性 > 样本量 |
| 结论撰写者 | 撰写结论、置信度与结论反转条件 | 每个事实断言必须引用证据 ID；证据不足时不得强行下结论 |

所有角色共享红线：不构成投资建议、不荐股、不预测涨跌、不编造数据。荐股式输入（如「该不该买 X」）会被拦截并引导改写为可验证命题。

## 数据

| 数据源 | 覆盖 | 接入方式 |
| --- | --- | --- |
| 扶摇 | A股行情快照/历史K线、财务报表与指标、估值、指数/板块 | REST（`FUYAO_BASE_URL` / `FUYAO_API_KEY`） |
| iFinD MCP | 公告、研报、行业及公司数据 | MCP Streamable HTTP + JSON-RPC 2.0（`IFIND_MCP_URL` / `IFIND_MCP_TOKEN`），工具按关键词匹配，不依赖具体命名 |
| 内置快照 | 演示案例与测试标的的真实公开数据 | `src/lib/data/snapshot-data/`，标注报告期与出处 |

降级策略：真实源未配置/超时/限流/故障 → 自动降级内置快照；快照未命中 → 载荷标 empty，证据为「无法验证」。所有降级与异常在证据载荷与页面中如实标注，缓存仅对成功结果生效（5 分钟 TTL）。

## 边界

- **合规**：产品定位为信息整理与证据验证工具，不构成投资建议；拒绝荐股式提问并引导为可验证命题；页面固定展示免责声明。
- **数据真实性**：AI 不生成数值；快照数据来自真实公开财报/公告并标注出处；证据载荷展示原始返回，可人工复核。
- **失败模式**：LLM 输出不合规自动修复重试（最多 3 次）；接口异常给出明确降级而非空结论。

## 未做事项（如实声明）

- 多用户与账号体系（当前为单用户演示级，研究任务存浏览器 localStorage，支持导出/导入）
- 生产级缓存、限流与审计日志
- 实时行情推送与定时监测（反转条件目前提供监测查询定义，未做自动轮询）
- 回测、量化信号与买卖建议
- 数据库持久化（研究任务仅本地保存）

## 技术栈与目录

Next.js 15（App Router，SSE 流式）+ TypeScript + Tailwind CSS；LLM 为 DeepSeek（OpenAI 兼容接口）。

```
src/
├── app/
│   ├── api/verify/     # 主链路 SSE 接口
│   ├── api/followup/   # 追问接口
│   ├── api/health/     # 数据源/LLM 配置状态
│   └── page.tsx        # 主页面（状态编排 + 流式渲染 + 比较/研究任务）
├── components/         # 输入区 / 验证视图 / 任务抽屉 / 公共 UI
└── lib/
    ├── pipeline/       # 澄清 → 拆解 → 证据 → 仲裁 → 结论 → 追问
    ├── data/           # DataProvider 适配层（扶摇/iFinD MCP/快照）+ 路由降级
    ├── prompts.ts      # 四类 AI 角色提示词
    └── types.ts        # 领域模型
```

## 部署

当前线上部署：**https://thesis-lab-iota.vercel.app**（Vercel 免费版，Next.js 零配置，环境变量为 `.env.example` 中的各项密钥）。主链路为 SSE 流式响应，接口已设置 `maxDuration=300`。

- **Vercel**：导入本仓库 → 在 Project Settings → Environment Variables 中配置密钥 → Deploy。
- **自建服务器（国内访问最稳）**：任意 Linux 服务器 `npm install && npm run build && npm start`（如阿里云/腾讯云香港轻量，无需备案）。
