# 需求分析与产品方案（v1.0 · 已确认）

> 项目：同花顺 2026 校招测评 · AI 产品经理岗 ·《投资命题与多证据验证》
> 状态：关键决策已确认（2026-11-21），进入开发。本文档最终会演化为 README 的「用户、设计、AI 角色、数据、边界、未做事项」六要素。

## 1. 项目背景

- 硬性时限：**收到题目后 48 小时内**完成并提交（题目附件「做题时间」）。
- 目标：设计并实现一个 AI 产品，把投资命题拆成可验证子问题，调用真实数据和原始材料，形成支持、反对与无法验证的证据链，并明确哪些信息变化会改变当前结论。
- 可使用的数据：扶摇（A股行情快照/历史K线、财务报表与指标、估值、指数/板块）；iFinD MCP（公告、研报、行业及公司数据）。

## 2. 题目拆解：评审在考察什么

| 题目要求 | 考察点 |
| --- | --- |
| 主链路：拆解、澄清并修订命题；组织支持/反对/无法验证证据 | Agent 产品设计 + 工程落地能力 |
| 可追溯结论 + 证据冲突处理 | 证据工程 + 诚实性设计（不编造、不回避冲突） |
| 继续比较、追问、保存为研究任务 | 产品完整性、持续交互设计 |
| Web URL + 源码仓库 + README（用户、设计、AI 角色、数据、边界、未做事项） | 工程规范与文档能力 |
| 60–180s 演示视频 + AI 使用/验证记录 + 测试说明；覆盖主链路、接口异常、合规边界 | 质量意识、测试意识、合规意识 |
| 扶摇 + iFinD MCP 真实数据调用 | 数据工程 / MCP 工具链使用能力 |

## 3. 目标用户与场景

- **用户**：会形成投资命题的投资者、研究员（非量化专业用户），例如「盈利改善来自主营业务」这类定性判断的提出者。
- **核心场景**：脑海中有一个判断（命题）→ 想知道它是否经得起数据检验 → 需要一份**能一路回到原始数据**的结论，而不是一句观点。
- **反场景（明确不做）**：荐股、涨跌预测、自动交易、回测。

## 4. 产品定位

一句话：**把一句投资命题变成「可验证子问题 + 支持/反对/无法验证证据链 + 可追溯结论 + 结论反转条件」的 AI 研究助理。**

- 名称（拟定）：「命题验证台 · Thesis Lab」（备选：论证实盘、EvidenceDesk）。
- 差异化设计（也是评分点）：
  1. **证据账本**：每条证据 = {子问题, 数值, 来源, 原始材料引用, 获取时间}；结论逐条引用证据 ID，全程可回溯。
  2. **诚实的第三类**：数据拿不到就标「无法验证」，绝不补全猜测——防幻觉是产品红线。
  3. **结论反转条件**：明确「什么信息变化会改变当前结论」，形成可监测的触发清单。
  4. **冲突显性化**：证据冲突不隐藏，而是展示冲突对 + 按显式规则仲裁。

## 5. 主链路设计

```
命题输入 → ① 澄清与修订 → ② 拆解子问题 → ③ 数据采集 → ④ 证据链构建
        → ⑤ 冲突处理与结论 → ⑥ 结论反转条件 → ⑦ 追问 / 比较 / 保存为研究任务
```

各环节要点：

1. **澄清与修订**：解析命题要素（标的、时间窗口、指标口径、断言方向）；识别歧义（如「盈利改善」指归母还是扣非？对比基准是什么？）；以对话逐项确认，输出「修订后命题」，修订记录可追溯。
2. **拆解子问题**：每个子问题标注验证口径、数据需求、数据源（扶摇 / iFinD / 公告 / 研报）；允许用户人工增删改。
3. **数据采集**：数据适配层统一调用；公告、研报等原始材料以可点击引用呈现。
4. **证据链**：每个子问题 → 证据条目（支持 / 反对 / 无法验证 / 部分支持 + 来源引用）。
5. **冲突处理与结论**：显式列出冲突对 + 仲裁规则（口径差异、时间窗口、来源权威性、样本量）→ 结论（支持 / 部分支持 / 不支持 / 无法判断）+ 置信度 + 证据索引表。
6. **反转条件**：具体阈值或事件，如「若下期扣非增速超过归母增速，结论翻转为支持」。
7. **后续动作**：多轮追问（保留上下文）；两个命题 / 两次验证结果的对比视图；一键保存为研究任务，可再次打开、继续追问。

| FR-03 | 子问题拆解展示（可人工增删改） |
| FR-04 | 证据链构建（三分类 + 来源引用可点击） |
| FR-05 | 结论与置信度 + 证据索引表 |
| FR-06 | 证据冲突展示与仲裁说明 |
| FR-07 | 结论反转条件清单 |
| FR-08 | 多轮追问 |
| FR-09 | 命题 / 验证结果比较 |
| FR-10 | 保存为研究任务并可再打开 |

## 7. 非功能需求（NFR）

- **可追溯性**：证据链记录不可变；结论引用证据 ID。
- **真实数据原则**：所有数值仅来自数据接口或内置数据快照，AI 不产出任何数字。
- **异常处理**：明确降级策略与重试；证据缺失时结论置信度相应下调。
- **合规**：免责声明（不构成投资建议）、第三方数据来源标注。
- **性能**：单次验证 ≤ 2–3 分钟，过程流式展示。
- **演示可靠性**：内置数据快照保证任何环境（含无凭证评审环境）都能跑通主链路。

## 8. 数据层设计

- 扶摇：行情快照 / 历史K线 / 财务报表与指标 / 估值 / 指数与板块。
- iFinD MCP：公告 / 研报 / 行业及公司数据。
- 统一 `DataProvider` 接口，三种实现：
  - `FuyaoProvider`：扶摇真实接口（需凭证）；
  - `iFinDProvider`：iFinD MCP 客户端（需访问）；
  - `SnapshotProvider`：内置真实公开数据快照（真实财报、公告节选，标注报告期与出处），用于演示、测试与无凭证兜底。
- 同一验证任务中三种来源可混合使用；每条证据如实标注来源。
- 查询结果短期缓存，减少重复调用。

## 9. AI 角色设计（README 需提交）

- **命题分析师**：解析命题要素、生成澄清问题、拆解可验证子问题。
- **证据组织者**：把数据结果组织为证据条目并归类（归类逻辑可审计）。
- **冲突仲裁者**：按显式仲裁规则处理证据冲突。
- **结论撰写者**：基于证据索引撰写结论与反转条件。
- **角色边界**：AI 不生成数值、不荐股、不预测涨跌；一切事实主张必须带来源引用。

## 10. 合规与边界

- 定位声明：信息整理与证据验证工具，**不构成投资建议**。
- 拒绝处理：「该不该买 X」→ 引导改写为可验证命题（演示视频展示点）。
- 无法验证 ≠ 猜测：无数据时明确标注，绝不补全。
- 数据来源标注与第三方数据免责。

## 11. 演示案例设计（已选型：光智科技 300489.SZ）

- 命题：**「光智科技 2024 年盈利改善主要来自主营业务」**
- 选型依据（据中国证券报·中证网 2025-03-16 报道）：
  - 2024 归母净利润 1225.71 万元，同比扭亏（上年亏损约 2.41 亿元）→ 支持「盈利改善」的素材；
  - 2024 扣非净利润 -3715.56 万元，主业仍亏损 → 反对「来自主营业务」的直接证据；
  - 非经常性损益合计 4941.27 万元（资产处置收益 3783.12 万 + 政府补助 2333.88 万）→ 揭示盈利来源；
  - 公告未逐项披露的细节 → 「无法验证」项。
- 预期结论：不支持（命题被证伪）——如实展示「诚实的结论」也是产品卖点；冲突仲裁演示口径差异（归母 vs 扣非）。
- 反转条件示例：「若 2025 年报扣非净利润转正且增速超过归母增速 → 结论翻转为支持」。
- 数据来源：待扶摇凭证到位后以真实接口数据为准（内置快照数据从接口返回捕获，标注报告期与出处）；若凭证无法及时到位，使用上述公开报道数据并如实标注出处。

## 12. 技术方案（已确认）

- **全栈**：Next.js（TypeScript，App Router，SSE 流式输出 Agent 过程）。
- **LLM**：DeepSeek（OpenAI 兼容接口，deepseek-chat）。
- **数据**：扶摇真实接口 + iFinD MCP 真实调用（统一 `DataProvider` 适配层）；`SnapshotProvider` 内置真实公开数据快照，作演示、测试与接口异常降级兜底。
- **持久化**：研究任务存浏览器 localStorage（演示级单用户），支持导出/导入。
- **部署**：海外免费平台（Vercel 或 Render，按账号情况）。
- **仓库**：GitHub 公开，README 含六要素。
